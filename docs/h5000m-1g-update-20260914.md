# H5000M 1G minimal 公共基线同步

本轮以 `f14d6cf327cb69c81cc5865c8b47b074469b5fb1` 为基础，公共代码
参考 4G `21ad48ae6e502d29e8ab3bf3cc247df59c5cd4d4`。旧版本固定于本地
`backup/h5000m-1g-minimal-before-4g-sync-20260914`；常用版分支不移动。

## 来源与下游差异

厂商基线从 `1927a9e` 更新至 `30fbc1d`，四个 feed 的完整提交见
`config/h5000m-source.lock`。1G 发布仓库采用源码快照历史，因此通过固定
提交差异导入，不合并厂商完整历史。未采用厂商通用 TurboACC 前端、已经删除的
BCM Full-cone 补丁和无效的 ifdown 普通文件；保留 MTK-only TurboACC 和
netifd 安装时创建的 ifdown 符号链接。其余厂商补丁保留顺序。

Argon 使用 4G 固定的本地主题包及独立 SHA256 清单。保留 1G 自包含 datconf，
不引用其他构建树的源码缓存。Modem 同步实际 AT 端口、AT 就绪返回值、锁释放
和元数据修复；保留原扫描器、TD Tech/MT5700M 和 quectel-CM-5G。

mtk-smp 内置并加入 `hiveton,h5000m-1g` 分派。默认以太网 RPS 为 0xe，
RX0–3 IRQ 对应 CPU0–3，TX 完成 IRQ 对应 CPU1。这是来自 4G 的策略，
仍需 1G 实机负载验证，不等同于已证明最优。

内置精简 TurboACC 及中文菜单“网络加速”、Modem 中文包、f2fsck。
继续排除 FRP、Nikki、Subpipe、Zapret2、NatMap、短信 LuCI、NFQUEUE
及无关存储组件。所有选中软件包为 built-in，不构建全量 kmod。

eMMC 升级保留 1G 的 96 MiB 容量检查，并同步错误返回和 fitrw 清理边界修复。
风扇控制、debugfs 安全挂载与 4G 已相同。无线默认设置不变。

## 1G 专用边界

- 内存 1 GiB，eMMC 7818182656 字节（15269888 个 512 字节扇区）。
- 原 emmc-comb ATF、1G U-Boot、DDR52，不启用 HS200/HS400。
- FIT 与 BOOTM 上限均为 96 MiB，加载地址 0x48000000。
- recovery 为 128 MiB，production 使用剩余空间；没有 data 分区。
- 仅导出 1G 镜像和启动链目标；不能使用 4G 的启动链工件。

启动链旧哈希继续保留在 source lock 中。新构建若不匹配，必须单独审查差异，
不得以重新计算哈希代替审查。本轮不刷写设备，不推送远程仓库。

## 构建与验收

在独立干净目录生成 `config/h5000m-1g-minimal.config` 对应配置，使用
`make -j12 V=s`。仅可复用独立复制的源码下载缓存，工具链、build_dir、
staging_dir、tmp 均重新创建；feeds 使用各自固定提交的独立检出。

执行 `scripts/h5000m-1g-verify` 及其 `--artifacts` 检查；工件检查覆盖
GPT 主备表、FIT metadata、96 MiB 边界、manifest 和启动链 SHA256。
内核/私有层由 `docs/h5000m-1g-vendor-manifest.sha256` 校验。

本文件记录同步设计，不宣称构建或实机通过。实际构建结果追加到此文档；
1G 实机启动、同代升级、MT7992/HNAT 和高负载测试均留待设备验证。

### 干净构建结果

独立目录 `immortalwrt-h5000m-1g-build-20260914` 从 `d76d051` 构建，
`make -j12 V=s` 返回 0。工具链、Linux 6.6.94、选中模块、ATF/U-Boot
和两种系统镜像均重新编译。eMMC 返回值/清零边界和 0/1/2 无线接口下的
SMP 映射隔离测试通过。未修改 1G 常用版和 4G 分支。

production 镜像为 21,562,163 字节，SHA256 为
`13381f2e449be3df06afb63089829ac5fc756e5bbb73f2de0e62f25bd8c1dcbb`；
recovery 为 18,677,760 字节，SHA256 为
`a07911ed7b55b0008a24e0fc81a22d01cbfea70df9f46910ebb0038fab00da1c`。
主备 GPT 与旧 1G 工件逐字节相同。

启动链差异单独审查：BL2 长度仍为 250,544 字节，仅 6 个构建时间字符和
末尾 32 字节摘要变化；FIP 长度仍为 676,056 字节，仅 48 个时间/版本字符
变化。U-Boot ELF 的 `.text`、`.text_rest`、运行数据和重定位段相同；
只读字符串与不进入 FIP 的 ELF 调试路径/编译器标识变化。
旧哈希继续保留，新构建哈希使用独立 `H5000M_1G_BUILD_*` 锁项。
系统升级无需写入这些启动链产物。
