# H5000M 1G minimal：当前有效设计

适用于 MT7987、1 GiB DRAM、8 GB eMMC，板型 `hiveton,h5000m-1g`。
本页描述 2026.09.14 minimal；不适用于 4G 改装板，也不描述历史常用版。
首次安装见[迁移手册](h5000m-1g-install.md)，实际测试范围见
[发布记录](h5000m-1g-release-20260914.md)。

## 来源与改动边界

厂商基线为 `30fbc1d6deba23c0e850185021e9ee42214925eb`，Linux 6.6.94。
本轮引入从 `1927a9e` 到该提交的公共更新，参考 4G 公共提交
`21ad48ae6e502d29e8ab3bf3cc247df59c5cd4d4`，没有复制 4G 内存、GPT 或加载地址。
快照仓库通过审计差异导入上游更新，具体来源见
[锁文件](../config/h5000m-source.lock)和[同步记录](h5000m-1g-update-20260914.md)。

| 层次 | 继承的厂商能力 | 本项目下游改动 |
|---|---|---|
| MTK 内核/驱动 | 匹配的 MediaTek 内核补丁、MT7992 HWIFI、WED/WARP、HNAT、PHY/PCIe 支持 | 保留补丁顺序及完整私有源码，叠加 H5000M 板级适配；不是重写 MTK 驱动 |
| 启动链 | MT7987 ATF、emmc-comb 初始化、MediaTek U-Boot 支持 | 独立 1G 设备目标、DDR52、FIT 容量检查、串口/TFTP 启动及恢复环境 |
| 存储 | FIT、SquashFS、fitblk、F2FS | 固定 1G GPT，生产分区用尽剩余空间，修复升级配置归档和清零边界、失败返回值 |
| 网络 | ImmortalWrt 网络栈和厂商硬件加速 | MTK-only TurboACC、“网络加速”菜单、H5000M SMP 映射 |
| 温控 | MTK thermal/PWM 支持 | 五点曲线控制及 LuCI、传感器失败全速保护 |
| 蜂窝 | 原私有扫描器、Quectel 拨号、Modem LuCI | TD Tech/MT5700M 支持及最小 AT/锁修复，不整包换成另一套 Modem 架构 |
| 构建 | ImmortalWrt 构建系统及四个 feeds | 固定提交、板级/厂商 SHA256 清单、自包含 Argon/datconf、minimal 包边界校验 |

## 启动链与存储

1G 内存范围为 `0x40000000` 起的 1 GiB。FIT 读取地址 `0x48000000`，
kernel load `0x40000000`，DTB load `0x4ff00000`。
`CONFIG_SYS_BOOTM_LEN=0x6000000`，recovery/production 的 FIT 本体均不得超过
96 MiB。128 MiB 的 recovery 分区不是 128 MiB 的可加载 FIT 额度；
production 的剩余空间供 F2FS overlay 使用，不意味着可以加载数 GiB 的 FIT。
不启用 FIT 签名验证；SHA256 用于文件完整性核对，不替代可信发布来源。

eMMC 使用 8-bit DDR52，不启用 HS200/HS400。实际卡为 15,269,888 个
512 字节扇区，即 7,818,182,656 字节；不是正好 8 GiB。

| 区域 | 首扇区 | 末扇区 | 大小 |
|---|---:|---:|---|
| 主 GPT（含保护 MBR） | 0 | 33 | 17,408 B |
| ubootenv（两个 256 KiB 副本） | 8192 | 9215 | 512 KiB |
| factory | 9216 | 17407 | 4 MiB |
| fip | 17408 | 25599 | 4 MiB |
| recovery | 32768 | 294911 | 128 MiB |
| production | 294912 | 15269854 | 14,974,943 扇区，约 7.14 GiB |
| 备份 GPT | 15269855 | 15269887 | 16,896 B |

未列出的间隔保留；BL2 位于 eMMC **boot0 硬件分区**，不是 GPT 中的分区。
无 p6/data，不默认安装 block-mount 或独立数据盘自动挂载配置。
`/dev/fit0` 为只读 SquashFS，`/dev/fitrw` 为 F2FS overlay。

升级从新 FIT 的 SquashFS 长度计算页面对齐后的真实 fitrw 起点，避免把
`sysupgrade.tgz` 写到 FIT 填充末尾而不能恢复配置；不保留配置时在同一真实边界
清除八个扇区，禁止通用逻辑再次越界清零。失败必须返回错误，不能继续报告成功。
该边界随镜像变化，不得将本次发布的数值写死到后续升级操作。

## 网络与设备服务

- LAN 默认 `192.168.1.1`，WAN DHCP，登录 `root/admin`；不是原厂网络参数。
- 保留 CID 派生 MAC、factory EEPROM 校验与回退路径。校准数据属于每台设备，
  不分发通用 factory，不复制另一台设备的 MAC 或 EEPROM。
- 保留 HNAT/WED/WARP。TurboACC 前后端仅提供 MediaTek HNAT、IPv4/IPv6、
  绑定速率、TCP CCA 和 PPE 状态；不是 SFE、软件卸载或 BCM/XT Full-cone 界面。
- mtk-smp：RX0–3 分别 CPU0–3，TX 完成 IRQ 为 CPU1，以太网 RPS `0xe`。
  已核对设备设置，但均衡程度取决于流量；该映射不保证所有业务均匀占满四核。
- 风扇默认曲线 `20:0,35:0,50:77,70:159,100:255`，严格五点、横轴 0–100°C，
  首末端外保持端点 PWM。传感器合法范围 -40–125°C；每轮三次快速读取均失败才
  累计一次，默认 10 轮进入 PWM 255，重新读到温度即恢复。默认主循环间隔 3 秒；
  停止/正常退出也尝试写 255。曲线和失效次数可从 LuCI 设置。
- Modem 保留原扫描器与 `quectel-CM-5G 1.6.4-r1`，LuCI 为最小修复版
  `1.4.5-r4`：实际 AT 端口、就绪返回状态、锁释放和元数据修复。
  MT5700M 使用 TD Tech AT 和 ECM/NCM，不依赖 Quectel-CM 数据拨号。
  `3gnet` 是运营商 APN 名称，不代表仅使用 3G；实际制式由注册状态决定。
- Wi-Fi 没有默认强制关闭。未接天线时不要启用射频。

## 镜像包边界

精确版本以 Release 的 `.manifest` 为准，配置入口为
[`h5000m-1g-minimal.config`](../config/h5000m-1g-minimal.config)。选中包全部 built-in；
源码里存在其他厂商包不表示它们进入镜像。

内置 LuCI/中文、Argon、软件包管理、SSH、基础防火墙/DNS/DHCP、MT7992 私有链、
HNAT/WARP、mtk-smp、精简 TurboACC、风扇控制、Modem/中文、Quectel-CM-5G、
`sms-tool`、QMI/MBIM/串口/蜂窝网络驱动、F2FS 工具。保留 sms-tool 是因为 Modem
有实际依赖，**没有独立短信 LuCI**。保留原 Quectel 包用于其私有依赖与对应硬件兼容。

不内置 Nikki/Mihomo、FRP、Subpipe、Zapret2、NatMap、ByeDPI、Passwall、
ModemManager、短信 LuCI、NFQUEUE、透明代理专用 TUN/TPROXY、USB 存储、
FAT/NTFS/exFAT、独立 data 管理、ttyd、rclone、Ruby、bash 和 htop。
基础防火墙自身的 flow 模块或设备依赖不等于重新启用了透明代理/Full-cone 功能。

关闭 DEVEL、自动重编译、内核调试信息/BTF、DEBUG_KERNEL、FTRACE、KPROBES、
PERF 等。debugfs 为 MTK 私有驱动的实际依赖而保留，由标准启动路径以
`nosuid,nodev,noexec,noatime` 挂载；不以强行删除内部 ABI 换取表面上的精简。

## 可复现与验证边界

四个 feed 固定为 packages `278a4d2`、LuCI `a5c40d1`、routing `946e9ff`、
telephony `92892fa`，完整哈希见锁文件。保留 ifdown 链接修复、自包含 datconf，
minimal 不依赖同级 Subpipe、Zapret2 或 wrt_packages 仓库。
独立干净构建、内核和选中模块及工件检查已完成；不构建全量 kmod。

本次设备验证不能证明原厂首次迁移、长期稳定性、WAN 吞吐、真实 HNAT 业务、
5G 拨号或 Wi-Fi 射频均通过。历史常用版透明代理记录不属于当前 minimal 能力承诺。
